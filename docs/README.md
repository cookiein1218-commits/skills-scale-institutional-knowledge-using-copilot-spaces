# OctoAcme Project Management Documentation

This folder contains OctoAcme's project management methodology for delivering customer-focused, iterative software work with clear ownership, measurable outcomes, and continuous improvement.

## Overview

OctoAcme runs projects through a lightweight lifecycle designed to help cross-functional teams align early, plan deliberately, execute with visibility, and learn after each release. The methodology emphasizes:

- Customer-first delivery of value
- Iterative and incremental releases
- Clear ownership and accountability
- Data-informed decision making
- Psychological safety and continuous learning

The documents in this folder provide a consistent, practical framework for project initiation, planning, execution, release, and retrospective practices.

## How to use these docs

- Start with the [Project Management Overview](octoacme-project-management-overview.md) for a broad summary
- Use the lifecycle guides as the operational playbook during each project phase
- Keep the project one-pager, risk register, and status artifacts current in the project repository
- Use supporting docs to tailor communication, delivery, and governance practices for your team
- Add process-specific guidance to `.copilot/` when using Copilot Spaces so project context remains available during delivery work

## Recommended reading path for new team members

1. Read the project overview to understand the methodology and core roles
2. Review the initiation and planning guides before starting a new project
3. Use execution and release docs during active delivery
4. Finish with the retrospective guide to improve process and outcomes over time

## Summary of OctoAcme's process approach

OctoAcme's project management process is built around a pragmatic, iterative cadence:

- Start with clear problem framing and stakeholder alignment during initiation
- Turn approved work into a prioritized backlog and release plan during planning
- Deliver incrementally with metrics, quality checks, and visible progress during execution
- Release with standardized deployment and communication controls
- Close each cycle with retrospectives and action items that improve future delivery

This approach balances speed with accountability, giving teams a repeatable method for shipping value while improving trust, transparency, and learning.
